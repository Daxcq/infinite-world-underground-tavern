# 按用户流程图编排的对话与状态机 v2

日期：2026-11-08。用途：设计与审阅。

**后续接入更新：** 已接入 Godot F5 主流程，使用用户确认的独立试玩数值；实际支持范围与仍停止的分支见 [Godot 对话接入说明](../../game/对话接入说明.md)。本文件的条件文本仍是设计契约，实际事件与守卫由游戏控制器执行。

## 本轮权威与变更

以本目录《原始流程图.png》为前两幕的结构底稿。用户本轮明确保留第三幕清桌及三类碎片；共渡成功不直接逃脱，改接清桌。用户又明确：**只处罚实际贡献更少的一方；同贡献双方受罚；玩家受罚才推进眼→手→心**。NPC 单独受罚不会消耗玩家器官。独狼只有玩家，失败责任归玩家。

这两次明确回复高于旧主方案、旧《第一人称3D赌桌调整方案》和 v1 对话稿中的相反描述。其余已确认内容继续沿用：俯视探索、落座第一人称、失眼转头补全观察、失手先放回托盘、失心接班、碎片跨桌保留且同类去重。

本次不引入独立的理智条。图上把“现实血量→理智值／生命值”及血量、状态列为待确认，故幻觉先作为场景状态；生命剩余器官数可由 `3 - player_penalties` 推导。正式失败次数、荷官怒意表现与玩家器官损失必须分开记录。

## 文件怎样使用

- 《对话节点.json》：唯一节点数据源，每个节点包含原图位置、触发事件、守卫、对白、选项、跳转、副作用和确认状态。
- 《节点逐条文案.md》：由节点数据生成，适合逐句审阅与交给制作人员。
- 《对话流程预览.html》：保留神秘、黑暗的哥特对话形式，同时可看分区流程、选择节点、检查状态契约。它是节点审阅器，跳转不表示守卫已成立，也不执行真实筹码结算。
- 《校验设计.py》：检查节点唯一、目标存在、起点可达、终点合法、分支守卫、对白编号及源图覆盖；同时生成文案表和嵌入数据的离线预览。
- 《设计验收.json》：区分拓扑检查、规则边界检查、浏览器检查与未决定项。

## 状态机的最小结构

使用一个分层流程状态加一个对话显示状态，避免把每句台词做成 Godot 节点。阶段分为：`SURFACE / TUTORIAL / DESCENT / TABLE_SETUP / STAKE / POOL / CLEAR / SETTLEMENT / END`。阶段内部用本稿节点 ID 驱动。UI 独立为：`CLOSED / REVEALING / WAIT_CONTINUE / WAIT_CHOICE / CONFIRMING / PAUSED`。

选择数据化节点加小型流程控制器，是因为编辑内容主要是对白、守卫与下一跳；无需为每句对白单建类，也不需要大型行为树或新的对话语言。本稿的条件与副作用是明确的设计契约，不是可直接执行的脚本表达式。

每条转移必须有 `event + guard + target + effects`。先检查来源节点、输入序号、守卫，再锁定动作；结算事务通过后进入下一节点。只有游戏逻辑能发送 `REVEAL_DONE / SETTLEMENT_DONE / TABLE_READY`；玩家不能用“继续”按钮伪造实际判定结果。

### 状态字段与持久范围

| 字段 | 范围 | 含义与约束 |
| --- | --- | --- |
| `run_id / action_id / settled_action_ids` | 一次游玩 | 同一个提交最多结算一次；重复点击、重复演出回调不再次扣筹码或器官 |
| `phase / node_id / ui_state / return_node` | 当前流程 | 暂停只挂起，恢复回原节点和原选中状态 |
| `intro_wine_taken / intro_wine_drunk` | 一次游玩 | 免费剧情酒；不是背包恢复道具 |
| `tutorial_initialized / tutorial_gold / rescue_wine_count` | 教学 | 初始 100 与 1 瓶只在初始化时发一次；重开对白不重复发物品 |
| `descent_reason / descent_done` | 一次游玩 | `VOLUNTARY / TUTORIAL_LOSS / UNPAID_PENDING`；酒面演出完成仅转场一次 |
| `mode / npc_id / npc_card_seen / dealer_card_seen` | 当前桌 | 三人／独狼；查看不等于选择；独狼的 NPC 贡献不伪造为零参加责任比较 |
| `player_chips / npc_chips / private_chips / public_pot` | 资源 | 金额变动仅在事务中提交；金币转筹码比例、新桌发放规则尚未定数值 |
| `promised_p / promised_n / actual_p / actual_n` | 本幕 | 口头承诺与实际出资分开；NPC 实投在提交前锁定，不能看到玩家实投后反改 |
| `dice_p / dice_n / dice_dealer` | 本幕 | 每方三骰，只掷一次；重开面板不会重掷；NPC 骰只对 NPC 可见 |
| `selected_dice / committed_dice / reserve_dice` | 本幕 | 用骰子 ID，不能只用点数去重；两枚 4 是两枚不同的骰子 |
| `pool_contrib_p / pool_contrib_n / dealer_total` | 本幕 | 只用真实投入点数比较责任；不看声称值，也不以保留骰数量代替贡献 |
| `responsible_party` | 一次结算 | `PLAYER / NPC / BOTH`；独狼失败恒为 PLAYER |
| `failed_rounds / dealer_anger_events` | 一次游玩 | 失败与怒意表现计数；不会直接决定玩家眼手心；怒意不额外改骰子规则 |
| `player_penalties / lost_organs` | 一次游玩 | 仅 PLAYER 或 BOTH 时增加；依次眼、手、心；已为 3 则终止，不再结算 |
| `key_types` | 一次游玩 | 集合 `{STAKE, POOL, CLEAR}`；首次对应幕胜利才加该类 |
| `next_pool_open_p / next_pool_open_n / betray_locked` | 跨下一桌一次 | 明牌诅咒只在下一次共渡实际开始时消费，不在看牌或中途退出时消费 |
| `held_object / selected_tool` | 桌面操作 | 失手后使用另一物件前先放回托盘；操作门禁不改变已选骰或结果 |

### 输入与防重复

- 人物对白只负责展示。`REVEALING` 下 E／Enter 只补全当前句；`WAIT_CONTINUE` 下一次输入才翻页。
- 有多个选项时不默认提交。金额、骰子或器官后果在确认页再次显示，默认焦点在取消。
- 确认后 `action_locked=true`，重复确认与过期节点事件拒绝；结算后按 action ID 去重。
- 打开角色卡、暂停、查看规则、读完一遍台词均不改资源，不重掷骰，不改变 NPC 已锁定策略。
- 普通探索对白可取消，恢复到原目标；已经提交的赌注不可通过 Esc 撤回。
- 对话与选项出现时释放鼠标、冻结观察转头；失眼遮蔽位于世界层，不能遮盖字幕和关键点数。

## 明确的判定边界

1. 底注比较：`actual_p + actual_n >= stake_required` 达标；少一枚不达标。独狼仅检查自己。
2. 共渡比较：`pool_contrib_p + pool_contrib_n >= dealer_total` 通过。原图说明段有“大于”，但实际分支写“≥”；沿用明确分支及已有规则，将相等统一判为通过。
3. 责任比较：`p < n` 罚玩家，`p > n` 罚 NPC，相等 BOTH；只在本幕失败时比较。胜局中贡献小不自动受罚。
4. 玩家受罚：第 1 次眼，第 2 次手，第 3 次心；NPC 单独受罚，`player_penalties` 不增加。
5. 合注／共渡通过才授予对应类碎片；只进下一幕不等于已经拿到下一类。教学无碎片、无器官代价。
6. 共渡私藏换算在胜局结算时做一次；保留骰按 ID 保留，并按面值产生已确认的私藏收益。失败不先发收益再追回。
7. 失败先冻结贡献→判责任→原子结算资源与器官→显示事实→继续或接班。NPC 惩罚与玩家器官在同一事务提交，不能因为两段台词重复付代价。
8. 清桌败方为责任者，不复用上一幕的贡献结果；清桌胜利才获得 CLEAR。

## 图中未决定或未接通的地方

本节属于设计缺口，不伪装成已经存在的游戏机制。数据将相关边标为 `pending` 或 `proposal`；预览以醒目标记展示。

- **Q01 付账出口：** 图中“不玩了→喝过免费酒必须付钱、无抵押物”的箭头没有接到明确结果。先写拦账对白与事件接口，付钱离开／强制入地下都不擅自定案。
- **Q02 清桌最后同毁：** 图外三幕补充未决定双方最后一骰同点的最终胜负。本稿保留待裁定分支，不能暗加重掷或直接判负。
- **Q03 教学救援酒的可达性：** 初始 100、底注 100、失败只没收实际投入时，单次筹资失败通常仍有余额；“失去全部筹码”无法自然在该固定样例触发。该分支仍保留 `gold==0` 守卫，不能为了展示它把普通失败改成没收全部。需后续明确是否有多轮教学／额外扣款。
- **Q04 数值：** 恢复酒回多少、正式底注与起手筹码、金币转筹码比例、换桌补筹、清桌道具效果范围、哑骰价格与独狼清桌时荷官的手牌来源未定。节点文本使用参数槽；未配置不允许真实结算，也不展示编造数字。
- **Q06 双方背刺的奖池分配：** 图中称背刺者最终胜利可独占；双方都背刺时谁先结算、如何防止同一奖池被重复独占，尚未指定。保留这一收益分支，但不创造双份奖池。
- **Q05 共渡失败后的可支付分支：** 图明确了扣除和“不够换则永远留下”，但付得起后的接线未画出。本稿建议结算后回组桌保留碎片，标为 proposal；不默认继续清桌，因为本轮没有合法生成其手牌与奖励。

## 对白与视觉约定

黑铁／旧金／暗酒红／骨白延续 v1。句子改为更神秘、克制的哥特表达：酒保把陷阱说成礼仪，荷官只报准确数字与裁定，同伴用“我们”掩饰自利，环境旁白呈现可感知的异常。规则行不用隐喻替代数字。

格式固定为：**人物名＋身份 → 一至三句正文 → 最多三项玩家意图 → 每项的实际后果 → 需要时单独确认**。NPC 供述始终标“声称／未验证”。未知数值只在设计审阅器显示参数，正式界面必须先插值再出现。

正式接入应直接读取现有 Godot 4.7.2 工程配置，不升级引擎。设计稿的拓扑校验与后续 Godot 运行测试分别记录；拓扑校验本身不代表所有对局分支或经济循环已经验证。
