# Godot 对话与三幕流程接入

日期：2026-11-08。运行版本：Godot 4.7.2，GDScript，Compatibility。

## 现在怎样玩

双击仓库根目录《开始试玩.cmd》，或导入 `game/project.godot` 后按 F5。

也可双击《进入地下赌局.cmd》，跳过教学直接进入地下主线，骰子仍正常随机。地下三人固定为玩家、选中的一位 NPC、酒保（承担荷官职能）。

路线：入口 → 正前方吧台 → 接过并喝下普通免费酒 → 左侧圆桌空位确认落座 → 两轮教学 → 幽光酒／教学失败转场 → 查看同伴与荷官卡 → 正式合注、共渡、清桌 → 合钥开门。教学结束选“不玩了”会走到原图尚未裁定的拦账分支，本次在那里停止。

- E／Enter 先补全当前句，再次输入才继续；多选项用上下键、Tab、Enter 或鼠标操作。
- 报价页输入承诺金额；下一步另选真实出资，最后确认扣款。确认页默认聚焦“再检查一次”。
- 投骰页先选策略，再逐枚点击骰子调整投入；数字相同的两枚骰子仍是两个独立物件。高亮表示选中投入。
- 赌桌对话期间点右上“环顾桌面”可收起对白；鼠标／A、D 环顾，E 返回原抉择，已掷骰与选择保留。
- 普通酒馆对白 Esc 可收起；在赌桌流程中 Esc 打开暂停。暂停不能提交赌注，恢复后保留焦点。
- 地下阶段不能起身返回地上。教学期间可从暂停菜单起身，重新落座后继续原节点。
- 地下查看人物卡时可从“桌边人物”下拉框任选七位客人之一；镜头转向对应人物，查看不扣款、不承诺组队。选人后模型移到桌边第三席，身份同步进入三幕流程；正式入局后不能中途换人。
- 失眼后桌面一侧被遮蔽，字幕与界面在遮蔽之上；失手后查看手骰，再拿道具需先点击“放回托盘”。投出手里的骰子本身无需额外放回。
- 清桌无骰时可购买 1 点哑骰，或认负。认负会再显示下一器官后果，默认取消；按“确认认负”才计入败局。

## 本轮真实接入的内容

载入 v2 的 59 个节点及 128 条带条件的对白，保留同一套状态与转移契约。正式流程由当前节点、事件、守卫、结算与下一跳驱动；没有把 JSON 中的描述性条件拿去 `eval`，也没有让玩家点击“胜利”来代替实际投骰判定。

两轮教学、三种酒的独立状态、NPC 与荷官卡、合注真实出资、共渡暗骰与供述、保留手牌与私藏换算、窥牌眼、哑骰、清桌逐轮比较、公共奖池分配、三类碎片去重、责任结算、眼手心进度与胜败结局均接入。同伴可从当前地下人物名单选择，先锁定策略与暗骰再接受玩家提交；不是固定胜利脚本。自动测试为可重复验收使用固定骰子夹具，正常 F5 仍随机掷骰。

只在正式败局中比较实际贡献：少者受罚，相同双方受罚；NPC 单独担责不会扣玩家器官，玩家第三次受罚才失心。合注失败后结束旧桌，重新选择同伴；已有碎片、受损状态与下一次明牌标记保留。明牌诅咒到下一次共渡开始才消费。

每次提交携带节点与版本号，重复／过期输入拒绝。资源结算还按 action ID 去重，防止重复扣款、发碎片和支付器官。取消出骰、暂停、环顾、重新打开对白不重掷，也不改变窥牌眼已经看到的对手暗骰。

## 用户确认的独立试玩配置

配置保存在 `data/playtest_balance.json`，没有改写设计稿中仍待平衡的最终参数。

| 项目 | 本次配置 |
| --- | --- |
| 恢复酒 | 回 40 金币；只限教学，消耗一次 |
| 正式基础筹码 | 玩家、NPC 各 100 |
| 金币转换 | 剩余教学金币按 1:1 转为玩家私藏；与基础 100 分开，所以可用总额可大于 100 |
| 正式底注 | 120 |
| 哑骰 | 10 筹码，1 点 |
| 新桌补充 | 可用余额少于 60 才补至 60；不覆盖已有私藏，不无条件重置为 100 |
| 窥牌眼 | 沿用设计示例 25 筹码；每人最多持有一件道具 |
| 改面骰 | 示例价格 40 保留；改点范围未定义，购买禁用 |

教学奖金未定，当前只返还成功教学的自有本金，不虚构额外奖金。恢复酒的破产入口保留原图 `余额=0` 守卫，没有为演示该入口把普通筹资失败改成吞掉全部余额。

## 仍停止在明确边界的分支

- **拦账出口 Q01**：未定酒费、支付与离席条件，不伪造通关或强制下沉。
- **最后同毁 Q02**：清桌双方最后一骰同点、一起销毁，未裁定胜负；不暗加重掷或默认败局。
- **双方背刺**：桌局最终胜利后奖池独占优先级未定，停止于清桌结果；不重复发同一份奖池。
- **共渡失败后付得起的下一桌**：原设计仅是 proposal，实际结算责任与器官后停止，不把该建议默认为已批准规则。
- **独狼正式局**：第三幕荷官手牌来源未定，所以入口显示原因并禁用；教学独狼仍可玩。

这些停止页可返回标题重新开始，不会偷偷随机决定规则。它们意味着当前是有清楚边界的可玩接入，并非已完成所有分支的正式发布版。

## 代码与数据

- `scripts/dialogue_flow.gd`：独立、可测试的流程与资源控制器；运行时条件过滤、变量插值、白名单事件处理、掷骰、责任与结算。
- `scripts/main.gd`：连接探索热点、落座、对话、环顾、黑场、器官视野和结局相机。
- `scripts/game_ui.gd`：暗黑哥特主题、正文与选项后果、金额输入、逐枚选骰、焦点和暂停。
- `data/dialogue_v2.json`：位于项目内部的运行适配副本。59 个节点的流程结构沿用源稿；N00／N01／N02 已结合工作区新增的地下人物名单与酒保／荷官角色卡适配文字、称呼和显示变量。源稿仍在 `设计/流程图对话状态机_v2/对话节点.json`；改稿时应合并适配，不能直接覆盖运行副本。

未引入新的插件、全局单例或第三方对话语言；未修改像素长廊独立小样入口。现有角色模型、坐姿和场景资产保留，逻辑点数以 UI 为准；骰子滚动、器官入骰、取放手部及接班发骰的完整动画、配音／音效和存档尚未制作。当前不表示所有模型外观都已完成哥特美术改造。

原有未定分支继续保留，尤其共渡失败后的续局、清桌最后同毁和双方背刺分账；本次场景与选人接入不补写这些规则。教学流程、地下主线与入口可重复运行，界面上的骰点仍是结算依据，实体骰子尚未绑定翻面动画。
